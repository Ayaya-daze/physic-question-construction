# 实施计划

版本：2026-07-27

本文是从当前可交付基线推进到比赛版本的执行清单。完整目标和指标见 [14-competition-project-plan.md](14-competition-project-plan.md)，参考项目的取舍依据见 [13-reference-project-review.md](13-reference-project-review.md)。

## 原则

1. 先保证资料不丢、不改错、可审核，再提高自动化率。
2. 正式题库只以题目正文、答案正文和局部资产为真源。
3. 知识点从用户导入的题目产生，不预置固定学段目录。
4. 比赛主链路由本项目实现；允许调用视觉识别 API 和 embedding API，不依赖完整外部 OCR、向量库或 Agent 系统。
5. 每个阶段必须有可重复测试、失败样例和量化结果。

### 组卷导出

- [x] 支持搜索词或知识点加题目数量进行候选召回。

- [x] 复制实际引用的局部题图并保留独立编译日志。

### 单用户批量运行

- [x] 后端单 worker 顺序处理，避免单用户批次互相争用。
- [x] 任务结束后统一重建索引。
- [x] 提供 Codex Skill 和 Agent Inbox 作为开发、人工批次修复与质量对照工具。

### 基线验证

- [x] 前端生产构建通过。

## P0：正确性与可评测性

### 1. 冻结基线

- [ ] 给当前版本建立竞赛基线标签。
- [ ] 建立不含私人资料、数据库和密钥的比赛分支。
- [ ] 固化一条全新机器安装与启动检查。

验收：按文档可在浏览器完成看题、搜索、选题和独立题答卷导出。

### 2. 建立脱敏真值集

- [ ] 覆盖原生文本 PDF、普通扫描、公式密集、跨页、含图、题答分卷和合一卷。
- [ ] 为每份资料标注大题边界、正文、答案、页码、局部题图和异常。
- [ ] 增加旋转页、坏图片、缺答案、重复题号和中断任务。
- [ ] 输出统一 JSON 报告，记录模型、耗时、调用量和失败样例。

验收：导入、检索和组卷改动都能得到可比较指标。

### 3. 重写安全物化器

- [x] 用来源哈希、逻辑题号和批内位置生成稳定且不冲突的 ID。
- [x] 预检正文、metadata、图片引用、文件类型和路径 containment。
- [x] 将完整候选写入同文件系统的 staging 目录。
- [x] 用正文、metadata 和资产全量哈希判断幂等与冲突。
- [x] 验证通过后原子重命名；失败回滚，并在服务启动时恢复中断的目录交换。
- [x] `human_review_needed` 和 warning 必须经用户明确批准后才能提交。

验收：重复导入新增题目为 0；缺图、路径越界、内容冲突和模拟中断均不污染 `questions/`。

## P1：自研批量导入主链路

### 4. 文件预检与页级调度

- [x] 识别 PDF、图片、Markdown、LaTeX、TXT、Word 和结构化 JSON。
- [ ] 判断 PDF 文本层可靠性、乱码、方向、清晰度和页面尺寸。
- [ ] 自行完成拆页、页面渲染、任务排队、限流、重试和单页恢复。
- [ ] 按来源哈希、页码、区域和 prompt 版本缓存 API 结果。
- [ ] 记录批次进度、每页路线、错误和模型调用量。

验收：失败页可单独重跑，已完成页不重复调用 API。

### 5. 证据块与选择性视觉 API

- [ ] 定义统一证据块：页码、归一化坐标、类型、Markdown/LaTeX、置信度和来源哈希。
- [ ] 原生文本资料走本地快速通道。
- [ ] 扫描页调用可替换的视觉 API，但不直接采用供应商的整卷 Markdown。
- [ ] 普通页只识别一次；漏题号、公式密集、跨页或图文归属不明区域才二次识别。
- [ ] 最终正文由已确认证据块按阅读顺序组装，只允许局部可追溯 patch。

验收：与逐页完整视觉识别对照，公布准确率、吞吐、审核时间和 API 调用量。

### 6. 拆题、答案匹配与题图

- [ ] 按可见大题号、版面范围和跨页关系拆题，不按预期题数补齐。
- [ ] 支持题目卷与答案卷配对、合一卷、集中答案和缺答案。
- [ ] 不调用模型补写来源中不存在的答案。
- [ ] 根据题目区域裁剪局部题图，使用稳定文件名并写入正文引用。
- [ ] 整页渲染图只进入证据层，不能进入题目 `assets/`。

验收：错挂图片、整页误用和缺失图片引用均为 0；答案匹配失败进入审核。

### 7. 审核工作台

- [x] 实现文件候选的 `needs_review -> committed/rejected` 阻断式状态机。
- [ ] 并排显示来源页区域、题目、答案、图片和 warning。
- [x] 支持编辑题目与答案、预览 Markdown/LaTeX、确认 warning、批准和驳回。
- [ ] 支持候选拆分、合并和从来源页裁剪局部题图。
- [ ] 允许只重跑单页、单区域或单题。

验收：所有阻断项只能经用户处理后提交，审核动作具有日志和来源追溯。

## P1：知识点与检索

### 8. 动态知识点

- [x] 只从正式题目的松散 metadata 派生知识点，不读取预设树。
- [x] 支持改名、合并、别名保留和频次统计。
- [ ] 增加显式确认与删除动作。
- [x] 将演示 seed 与生产知识点隔离。
- [x] 知识点页面直接筛选文件题库，不再跳到旧审核页。

验收：空题库没有预设知识树；导入新领域资料后可生成并治理相应知识点。

### 9. 本地混合检索

- [x] 使用 SQLite FTS5/BM25 完成关键词召回。
- [x] 支持通过可替换 OpenAI-compatible embedding API 生成真实 dense vector。
- [x] 本地保存 float32 向量、题目映射和索引 manifest。
- [x] 由项目实现余弦检索和 RRF 融合。
- [x] 支持按动态知识点筛题。
- [x] embedding API 未配置或临时故障时降级到本地索引与关键词检索，并在 manifest 记录错误。
- [ ] 建立查询真值集并测量 Recall@10、nDCG@10 和 P95 延迟。

验收：索引可从 `questions/` 完整重建；不依赖 Qdrant、pgvector 或其他外部向量数据库。

## P2：组卷与交付

### 10. 组卷工作台

- [ ] 让自然语言只解析为检索条件和排序建议。
- [ ] 显示候选题来源、知识点、命中原因并支持替换和排序。
- [x] 增加题目内容哈希、来源哈希、资产哈希、顺序和模板版本组成的导出 `manifest.json`。
- [x] 在编译日志中插入题目标记并返回最可能导致 TeX 编译失败的题目 ID。
- [ ] 在 TeX/PDF 主链路稳定后评估 Word 导出。

验收：从不同来源混合选题，生成含公式和局部题图的独立题目卷、答案卷及可编辑源文件。

### 11. 压力、部署与参赛材料

- [ ] 覆盖万题索引、百题组卷、大批次导入、重复执行、中断恢复和坏文件。
- [ ] 完成 Docker 一键启动、健康检查和运行数据持久化。
- [ ] 准备脱敏离线演示数据与 API 缓存。
- [ ] 扫描 Git 历史和发布包，排除 PDF、题库、数据库、密钥和运行输出。
- [ ] 完成演示脚本、指标图、失败边界、安装手册和备用录屏。

验收：全新机器可安装；无外部 API 时仍能演示已有批次的审核、检索、组卷和导出。

- 文件写入、候选审核、动态知识点、混合索引和组卷导出均已接入文件题库主链路。
- 自动化回归测试共 13 项，覆盖原子写入、幂等、目录交换中断恢复、符号链接拒绝、审核阻断、重复候选、同名题目稳定 ID、知识点治理、embedding 故障降级、缺图阻断和导出 manifest。
- 前端生产构建通过；浏览器实测知识点筛题、导入页和独立题答卷导出均无控制台错误。
- 已有 740 题隔离导入、200 题组卷和 24 项极端压力基线继续有效。
- 尚未完成的比赛核心工作仍是页级证据块、选择性视觉 API、答案配对、局部题图自动裁剪、真值集评测和万题级测试。

## 暂不实施

- 多租户、计费和公网权限系统。
- 固定题型 schema 和预设高中知识树。
- 让 LLM 生成题库外题目作为正式试卷内容。
- 复杂知识图谱、学习诊断和推荐算法。
- 将完整第三方 OCR 平台、向量数据库或 Codex Agent 设为比赛运行依赖。
- 在正确性、审核和评测未稳定前扩展大量模板或视觉包装。

## 推荐执行顺序

1. 真值集与统一评测。
2. 安全、幂等、原子的物化器。
3. 页级调度、证据块和选择性视觉 API。
4. 审核状态机与局部题图流程。
5. 动态知识点和真实本地混合检索。
6. 导出 manifest、压力测试和比赛交付。
