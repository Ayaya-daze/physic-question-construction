# 参考项目审查与采用决策

版本：2026-07-27

## 目的

本文整理比赛方案形成前审查过的三套参考实现，记录哪些思路进入本项目、哪些实现必须重写，以及判断所依据的验证结果。

参考包、原始样题、数据库和运行输出均只在本地用于研究，不进入 Git。比赛目标方案见 [14-competition-project-plan.md](14-competition-project-plan.md)。

## 统一审查口径

所有参考实现按以下标准检查：

1. 能否处理题目卷、答案卷分离或合一的真实资料。
2. 是否以页面和原文为证据，避免模型无依据改写。
3. 是否逐题入库，并保持“题目正文 + 答案正文 + 局部资产”的简单结构。
4. 重复运行是否幂等，失败是否会留下半成品。
5. 图片引用是否完整，是否误把整页截图当题图。
6. 待审核记录是否真的不能越过审核闸门。
7. 检索是否具有真实语义能力，知识点是否从输入资料生长。
8. 是否具备可安装、可测试、可恢复和可追溯的工程条件。

## 参考 A：exam-paper-pipeline-skill

### 可取思路

- 把导入拆为文件配对、OCR、语义分割、标签、原文切片和泄露检查等阶段。
- 让模型判断题目边界，最终正文按 OCR 原文坐标或证据块组装，降低模型改写题意和公式的风险。
- 考虑题目答案分卷、合一卷、集中答案和交替答案等不同布局。
- 把跨题内容泄露、评分标准误删和内容覆盖率纳入质量检查。

### 不采用的实现

- 固定卷号、私人盘符和模板占位命令使流程不可移植。
- OCR 命令、输出目录和验证逻辑存在不一致。
- 声明的状态机、断点恢复和部分阶段没有完整实现。
- Agent 权限过宽，存在全局结束进程或直接污染正式题库的风险。
- 缺少原子写入、安装检查和系统化自动测试。

### 决策

采用“模型判断边界、内容由来源证据组装”的原则，不复用原脚本。边界、状态机、安全写入和测试由本项目重新实现。

## 参考 B：physics-question-importer recording flow

### 可取思路

- 扫描页图像是事实来源，OCR 仅作为提示。
- 只按页面中可见的大题号拆分，不为满足预期数量而补题。
- 正式记录保持 `question.md`、`answer.md`、`metadata.yaml` 和局部题图。
- 用来源文件、试卷标识和可见题号生成稳定 ID。
- 明确整页 PDF 渲染图不能作为题目资产。

### 验证发现

- Inbox 最终仍调用随机 ID materializer，重复执行可能重复入库。
- 缺图或复制失败时会留下半成品目录，写入缺乏原子性。
- 资产路径未完成严格 containment 检查，存在目录越界风险。
- 幂等比较没有覆盖 metadata 和资产哈希。
- `human_review_needed: true` 只是标签，未真正阻断入库。

### 决策

沿用简单记录、稳定 ID 和视觉事实源原则；物化器、审核闸门、全量哈希和路径安全必须重写后才可进入主链路。

## 参考 C：clean-with-samples 系统包

### 可取思路

- 提供浏览器校正页面和导入后编辑能力。
- 增加可编辑 Word 题目卷、答案卷导出。
- 使用轻量摘要索引，避免列表页反复读取全部正文。
- 样例覆盖题目答案合一和题目答案分离两类输入。

### 实际验证

- 摘要索引的 3 项单元测试通过。
- Word 导出的 2 项测试通过。
- 相关 Python 文件语法编译通过。
- 后端环境未安装 `pytest`，归档本身没有形成可直接运行的完整测试入口。

### 主要问题

- 两套样例把整份试卷作为一条记录，没有验证生产级逐题拆分。
- Markdown 引用了多张 `images/*.jpg`，归档中没有对应局部图片，样例显示会缺图。
- materializer 仍存在幂等、原子写入和路径安全问题。
- 所谓“向量”是词元哈希桶，不是可证明的语义 embedding。
- 示例知识点文件可能被误用成预设知识树。
- 测试没有覆盖审核阻断、重复导入、失败回滚和完整端到端流程。

### 决策

浏览器校正、摘要索引和 Word 导出作为后续模块候选。样例数据不作为正确性真值，原 materializer 和哈希桶索引不合并到比赛主线。

## 综合采用矩阵

| 能力 | 采用 | 不采用 |
| --- | --- | --- |
| 内容真源 | 页面证据、原始文本块、局部修正 | 让模型无依据重写全文 |
| 题目结构 | 题目正文、答案正文、局部资产、松散元数据 | 固定选择题和解析步骤 schema |
| 题目拆分 | 可见题号、版面范围、跨页证据 | 按声明题数补齐或强拆 |
| 写入 | 稳定 ID、全量哈希、staging、原子提交 | 随机 ID、边处理边写正式目录 |
| 审核 | 阻断式状态机 | 只记录 `human_review_needed` |
| 图片 | 从来源页裁剪的局部题图 | 整页截图或不存在的占位图片 |
| 知识点 | 从已批准题目生成并由用户治理 | 预设高中知识树 |
| 检索 | 本地 BM25 + 真实 embedding + 融合 | 词元哈希桶冒充语义向量 |
| 组卷 | 正文拼入模板，题目答案分别导出 | 拼接来源 PDF 或题答混排 |
| 外部能力 | 可替换视觉 API、embedding API | 完整第三方 OCR/向量平台成为核心依赖 |

## 对当前仓库的直接要求

### 必须保留

- `questions/{id}/question.*` 与 `answer.*` 是正式题库真源。
- 原始 PDF、页面图和模型响应只属于来源或审核层。
- 题图必须是与具体题目相关的局部资产。
- 组卷从题目正文生成 TeX，并分别输出题目卷和答案卷。
- Codex Skill 可用于开发、人工批次修复和质量对照。

### 本轮已补齐

- 阻断式候选审核状态机，以及编辑、warning 确认、批准和驳回接口。
- 安全、幂等、原子的题目物化流程和目录交换中断恢复。
- 从正式题目派生的动态知识点，以及改名、别名、合并和筛题。
- SQLite FTS5、本地 float32 向量、可选真实 embedding API 和 RRF 融合。
- 包含题目、来源与资产哈希的导出 manifest，以及题目级编译错误定位。

### 仍需补齐

- 自研页级调度、证据块、视觉 API provider、缓存和单页失败恢复。
- 题目答案配对、候选拆分合并和局部题图自动裁剪。
- 动态知识点的显式确认、删除和质量评测。
- 统一脱敏真值集、检索指标和可重复导入准确率评测。

### 明确隔离

- 旧结构化数据库和固定题型页面只作为兼容层。
- Codex Skill 不成为比赛部署的必需运行时。
- 参考包、私人 PDF、人工校对文本、数据库、模型密钥和运行输出不得提交。
